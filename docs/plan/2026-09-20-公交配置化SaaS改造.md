# 公交配置化 SaaS 改造

## 1. 背景

`watch-gateway` 原先把个人上下班线路硬编码在代码里，并绑定全局 Authorization + Bark，只适合个人使用。需要改造成「一份配置文件驱动、hash 公开查询、可多人调用」的小型公共网关，同时尽量不大改现有车来了查询与旧 Watch 接口。

## 2. 开发目标

- 用一份 `config.yaml` 描述全部公交场景（城市、线路、起终点、场景、上游参数、hash、legacy、bark）。
- 保留旧接口 `GET /watch/bus/home`、`GET /watch/bus/work`（鉴权 + 可 Bark）。
- 新增公共接口 `GET /watch/bus/q/{hash}`：无鉴权、只返回 JSON、永不 Bark。
- 公共接口限流：同一 IP + 同一 hash，每分钟最多 4 次。
- 启动时校验 hash / legacy 唯一；冲突则进程失败退出。

## 3. 实现范围

### 本次实现

- 配置加载与校验（YAML）
- 路由改为配置驱动（含 legacy 映射）
- 新 hash 查询接口（JSON only）
- 进程内限流中间件（IP + hash，60s / 4 次）
- 示例 `config.example.yaml`（虚构数据，真实配置本地自备）
- Dockerfile / 启动参数支持指定配置路径（默认 `./config.yaml`）

### 本次暂不实现

- 用户注册、计费、管理后台
- 配置热更新 / 自动生成 hash
- Redis 或分布式限流
- 多副本共享限流状态
- 修改车来了协议、加解密逻辑

## 4. 技术设计

### 4.1 配置模型

见仓库根目录 `config.example.yaml`。校验规则：

- `hash` 非空、全局唯一；建议 8+ 位字母数字
- `legacy` 若填写，全局唯一
- 上游必填：`city_id`、`line_id`、`target_order`、`station_id`、`station_lat`、`station_lng`
- 展示字段：`city`、`line`、`scene`、`from`、`to`

### 4.2 接口

| 类型 | 路径 | 鉴权 | Bark | 限流 |
|------|------|------|------|------|
| legacy | `GET /watch/bus/{legacy}` | `Authorization: {auth_token}` | 配置 `bark: true` 时推送 | 本期不限 |
| 公共 | `GET /watch/bus/q/{hash}` | 无 | 永不推送 | IP+hash，60s≤4 |
| 健康 | `GET /health` | 无 | — | 无 |

公共接口找不到 hash → `404`；超限 → `429`。

### 4.3 限流

- key = `clientIP + "|" + hash`
- 窗口 60 秒，额度 4
- 单机有效；多副本各算各的

### 4.4 核心流程

```
请求 → 匹配路由
  ├─ legacy: 鉴权 → QueryRoute → 可选 Bark → JSON
  └─ q/{hash}: 限流 → 查配置 → QueryRoute → JSON（无 Bark）
```

## 5. 隐私

真实站点名、经纬度、token 只放在本地 `config.yaml`，已加入 `.gitignore`。开源仓库只保留脱敏示例。
